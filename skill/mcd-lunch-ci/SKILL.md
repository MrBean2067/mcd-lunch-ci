# 午餐流水线 mcd-lunch-ci

## 这个 Skill 解决什么

团队点午餐的真实瓶颈不是「不知道有什么吃的」，而是**一群人带着互相冲突的约束（预算、忌口、减脂、昨天刚吃过）谈不出一致方案**。群聊里拉锯 20 分钟，最后往往由嗓门最大的人拍板，还有人没吃上能吃的。

这个 Skill 把它当成一个**约束优化问题**处理，而不是让模型「推荐几个套餐」：

- 忌口 / 热量上限 / 预算 = **代码里的硬过滤**，模型没有权限放行过敏原；
- 团队总预算 = 整数背包 DP，在候选阶梯上求**精确最优**（有穷举对数测试证明）；
- 输出除了方案，还有「**谁妥协了、差多少钱**」和「**预算—满意度前沿**」。

## 何时用

用户说了这些就用：

- 「我们部门 6 个人中午一起点麦当劳，怎么点」
- 「有人不吃辣、有人减脂、有人 gluten 过敏，凑一单」
- 「人均 25 以内，8 个人，出个方案」
- 「昨天吃过麦辣鸡腿堡，今天别重复」
- 「预算加到 260 会不会好很多」（→ 用前沿对比作答）

不适用：单人点餐（直接调 MCP 就行，不需要求解器）；单纯问营养数据（用 `list-nutrition-foods`）。

## 工作流

### 1. 先跑一次 demo，确认环境可用

```bash
python -m mcd_lunch_ci demo
```

这一步**不需要任何 Token**，用的是随仓库带的真实门店菜单快照。跑不通就先解决环境问题（Python 3.10+，零第三方依赖），不要往下走。

### 2. 收集每个人的约束

从对话里抽取，抽不到的**逐项问清楚**，不要猜：

| 字段 | 含义 | 抽不到时怎么问 |
|---|---|---|
| `name` | 成员称呼 | 直接用用户给的名字 |
| `budgetYuan` | 个人预算（元） | 「每人预算大概多少？」 |
| `avoid` | 忌口标签 | 「有没有人不吃牛/猪/辣/油炸/乳制品？」 |
| `maxKcal` | 热量**硬上限**，`null` 表示不限 | 「有人需要控热量吗？上限多少？」 |
| `targetKcal` | 理想热量（软目标，影响满意度） | 「大概想吃多饱？正常一餐 700~900」 |
| `likes` / `dislikes` | 口味偏好，`{标签: 权重}`，权重 0~1 | 「有人特别想吃/特别不想吃某类吗？」 |
| `recent` | 最近刚吃过的主食名 | 「昨天谁吃过什么，要避开重复？」 |
| `note` | 备注，只用于展示 | — |

**`avoid` 只接受这些标签**（传中文会被判为无法识别）：
`beef` `pork` `chicken` `fish` `soy` `dairy` `egg` `gluten` `spicy` `fried` `caffeine` `salty` `sugar`

对照中文：牛肉 / 猪肉 / 鸡肉 / 鱼肉 / 大豆 / 乳制品 / 鸡蛋 / 麸质 / 辣 / 油炸 / 咖啡因 / 高盐 / 含糖。

**过敏原必须问出来，不能默认没有。** 用户说「有人乳糖不耐」就要设 `"avoid": ["dairy"]`。

### 3. 写 team.json 并跑求解

```json
{
  "budgetYuan": 200,
  "members": [
    {"name": "阿岚", "budgetYuan": 30, "avoid": ["pork"], "maxKcal": null,
     "targetKcal": 800, "likes": {"caffeine": 0.3}, "dislikes": {}, "recent": [], "note": "不吃猪肉"}
  ]
}
```

```bash
# 离线（零 Token，用快照价）
python -m mcd_lunch_ci run --offline --team team.json

# 实时（真实门店 + 官方核价，需要 MCD_MCP_TOKEN）
python -m mcd_lunch_ci run --live --team team.json --city 上海市 --keyword 静安寺
```

`--budget` 可覆盖团队总预算，用来做「加预算值不值」的对比。

### 4. 把结果讲成人话

必须转述这四件事，不要只贴一段终端输出：

1. **方案表**：每人拿到什么、多少钱、满意度；
2. **合计**：应付多少、人均多少、平均满意度；
3. **谁妥协了**：拿到低于自己理想的人，以及「他更想吃 X（¥N），差 ¥M」——这是最有用的一栏；
4. **预算—满意度前沿**：三档预算下的性价比，用于回答「要不要加预算」。

**热量列出现「未知」或「≥N」时，必须原样说明**：这些餐品的营养数据官方没有提供，缺失不等于 0 卡。不要把「未知」讲成「很低」。

### 5. 下单前必须停下来确认

```bash
python -m mcd_lunch_ci run --live --team team.json        # 只出预览载荷（默认）
python -m mcd_lunch_ci run --live --team team.json --confirm   # 真下单
```

**默认永远不加 `--confirm`。** 必须把方案表给用户看、得到明确同意、并确认门店与取餐方式后，才可以真下单。付款由人在手机扫码完成，Skill 不碰钱。

## 硬性护栏

- **不编造价格**：所有金额只能来自快照或 `calculate-price` 核价回包。核价失败就说失败，不要估。
- **不放行过敏原**：用户说的忌口一律转成 `avoid` 标签。求解器保证不放行；不要因为「这个套餐看起来没问题」就手动作废约束。
- **缺营养数据 ≠ 0 卡**：给某人设了 `maxKcal` 时，营养缺失的餐品不会进入他的候选（代码已保证）。报告出现「未知」就如实说。
- **不重复下单**：同一轮对话里已经出过订单，再次下单前重新确认，避免在门店留多张废单。
- **Token 不外泄**：Token 只写在项目根 `.env`（已 gitignore）或环境变量 `MCD_MCP_TOKEN`，绝不写进对话、代码或提交记录。

## 自检与排错

```bash
python -m mcd_lunch_ci doctor                      # 连通性 / 门店 / 菜单 / 核价，四步全绿才算通
python -m mcd_lunch_ci doctor --city 北京市 --keyword 国贸
python -m mcd_lunch_ci sync --refresh              # 重新同步真实菜单快照（换城市后建议跑）
```

常见报错对应：

| 现象 | 原因与做法 |
|---|---|
| `未找到 MCD_MCP_TOKEN` | 让用户在项目根 `.env` 里写 `MCD_MCP_TOKEN=...`，或 `--offline` 走快照 |
| `InfeasibleError` + 诊断行 | 某人的约束无解（预算太低/热量上限太紧/忌口太多）。**照诊断里的最小可行金额或最低热量去跟用户谈**，不要自行放宽约束 |
| 金额与官方核价差几十元 | 单价必须逐项核价，批量核价会摊满减折扣。本项目已按逐项核价实现，若自行改过代码需回退 |
| 餐品被归错品类 | 看 `docs/MCP_FIELD_MAP.md` 的品类推断规则，结构词优先于营销分类 |

## 边界

- 过敏原标签是从**餐品名**推断的，不是官方成分表。涉及严重过敏时，明确提示用户**以门店/官方成分表为准**。
- 只覆盖麦当劳在售菜单；企业团餐（`beType=6`）需要外送地址，当前链路走到店自取（`beType=1`）。
- 优惠券接口只返回标题与状态、不含金额与券码，因此**券不参与方案计算**，报告显示 0 张券是真实情况，不是 bug。
